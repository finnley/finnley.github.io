## 设置打开文件数

1、备份并修改limits.conf文件：
```bash
sudo cp /etc/security/limits.conf /etc/security/limits.conf.bak

sudo tee -a /etc/security/limits.conf > /dev/null <<EOF

# --- Custom Production Configuration Start ---
root soft nofile 655350
root hard nofile 655350
* soft nofile 655350
* hard nofile 655350
* soft stack 20480
* hard stack 20480
* soft nproc 655360
* hard nproc 655360
* soft core unlimited
* hard core unlimited
# --- Custom Production Configuration End ---
EOF
```

**modprobe br_netfilter**

让 Linux 内核立即加载一个名叫 br_netfilter 的内核模块。

**sudo modprobe br_netfilter** 这条命令的意思是：

让 Linux 内核**立即加载**一个名叫 `br_netfilter` 的内核模块。

### br_netfilter 到底是干什么的？

它是 **bridge + netfilter** 的组合模块，主要作用是：

让**桥接流量（bridge traffic）也能被 iptables / nftables 看到和处理**  
换句话说，就是让内核的防火墙规则（iptables）能够对**桥接网络**里的数据包进行过滤、NAT、 masquerade 等操作。

最典型的使用场景就是 **Kubernetes**（几乎所有自建 K8s 生产环境都会用到它）：

- pod 之间通信（尤其是基于 VXLAN、Flannel、Calico BGP、Calico VXLAN 等 CNI）
- kube-proxy 的 iptables 模式
- Service 的 ClusterIP 负载均衡
- NetworkPolicy 的网络策略生效

如果没有加载这个模块，经常会出现以下现象：

- coredns 解析不了名字（reply from unexpected source）
- pod 之间网络不通
- Service 访问不通
- NetworkPolicy 不生效
- kube-proxy 报警告或功能异常

### 生产环境执行这条命令有风险吗？

| 场景                        | 是否有风险 | 说明                                                                 |
|-----------------------------|------------|----------------------------------------------------------------------|
| 已经运行了重要业务的裸金属/虚拟机服务器（非 K8s） | **极低**   | 单纯加载模块，几乎不影响现有网络，除非你本来就在用非常特殊的桥接+防火墙组合 |
| Kubernetes 生产集群节点（kubeadm / kops / 手工部署） | **几乎无风险，反而是修复风险** | 99% 的生产 K8s 集群都要求加载这个模块，不加载才是最大的风险 |
| 已经加载过的机器再执行一次   | 无风险     | modprobe 会直接返回（模块已加载）                                    |
| 云上托管 K8s（EKS、GKE、AKS、CCE 等） | 不需要执行 | 云厂商通常已经在底层内核帮你处理好了                                 |
| 某些很老的内核 / 特殊裁剪过的内核 | 可能报错   | 模块不存在或已内置（built-in），执行会失败，但不影响系统运行         |

### 生产环境最推荐的做法（2024-2026 年仍然适用）

在所有计划跑 Kubernetes 的节点上，**提前永久启用**，而不是临时 modprobe：

```bash
# 1. 立即加载（幂等，可重复执行）
sudo modprobe br_netfilter

# 2. 开机自动加载（强烈推荐）
cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
br_netfilter
overlay          # 顺便一起开了，很多 CNI 和 containerd 也需要
EOF

# 3. 让 iptables 能看到桥接流量（Kubernetes 官方强烈要求）
cat <<EOF | sudo tee /etc/sysctl.d/99-kubernetes.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

sudo sysctl --system
```

### 总结一句话

在**准备部署或正在运行 Kubernetes 的生产服务器**上，`sudo modprobe br_netfilter` **不但没风险，反而是必须的**，不做反而有很大网络出问题的风险。

在**完全不跑容器/K8s 的普通业务服务器**上，基本没必要加载，没加载也不会有事。
